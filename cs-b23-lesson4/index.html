STEP 1 · QUESTION

AND, OR, NOT

0 – 10 min · B2.3.2
  • AND (and / &&): true only if both conditions are true.
  • OR (or / ||): true if at least one is true.
  • NOT (not / !): reverses true and false.
  • Range check: mark >= 0 and mark <= 100 (Python also allows 0 <= mark <= 100).

STEP 2 · EXPLORE

Precedence and brackets

10 – 25 min · B2.3.2
  • Order: NOT first, then AND, then OR (like × before +).
  • a or b and c means a or (b and c).
  • Use brackets to make conditions clear: (day == "Sat" or day == "Sun") and not raining.
✏️ Worked example: Evaluating step by step
  1. (day == "Sat" or day == "Sun") → (True or False) → True.
  2. not raining → not True → False.
  3. True and False → False.
  4. The outing does not go ahead.

STEP 3 · TEST

Short-circuit evaluation

25 – 40 min · B2.3.2
  • AND stops at the first False; OR stops at the first True: the rest is not evaluated.
  • Used to avoid errors: if count != 0 and total / count > 50: never divides by zero.

Your answers

STEP 4 · EXPLAIN

De Morgan in code

40 – 55 min · B2.3.2
  • not (a and b) is the same as not a or not b; not (a or b) is not a and not b.
  • Useful for rewriting "not valid" conditions: invalid mark = mark < 0 or mark > 100.
